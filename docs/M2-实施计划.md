## 1. 完成定义（DoD，docs/08 §4 验收口径）

- 七格式**真全通**：旧格式 `doc/ppt/xls` 转换、扫描 PDF OCR、版面分析、表格结构还原、三级降级链全部落地。
- **IR v1.0 冻结**（04 章）；完整性指标与质量评分**全部为真值**（不再有占位常量/恒 NULL/空壳字段）。
- corpus 扩到 **50+** 并接入 CI 回归。
- 四项量化门禁达标（基准机 8 核/16GB 无 GPU）：
  - 数字 PDF 文本覆盖率 ≥ 97%
  - 表格结构还原 TEDS：常规 ≥ 85% / 复杂 ≥ 75%
  - 多栏阅读顺序正确率（块级）≥ 90%
  - OCR 字符准确率（300dpi 中文扫描件）≥ 90%，且 OCR P95 ≤ 10s/页
- M2 完成后**重跑性能基线**并冻结为 NFR 门禁（L0 版面分析 ~3~5s/页 + OCR 会大幅改变 M1 那组数字）。

## 2. 全局前置约束（每个阶段都受它约束）

- **许可红线（决策 D4）**：新依赖必须非 GPL/AGPL。已核对合规：Docling MIT（模型 CDLA-P-2.0/Apache-2.0）、RapidOCR Apache-2.0 + onnxruntime CPU EP MIT、LibreOffice MPL-2.0（**进程隔离调用**不传染）、Qwen tokenizer Apache-2.0。每次加依赖必须：改 03 章 §6 禁用/登记表 → 收紧 `pyproject.toml` 版本区间 → `uv lock` → CI 的 `scripts/license_scan.py` 保持绿。
- **模型不塞 PyInstaller `datas`**：270MB+ 模型走 `docfactory.spec` 的 `datas` 会让 onedir 暴涨、analysis 变慢。应仿照 `office_convert.find_soffice()` 的 `_bundled_candidates()` 模式，新增 `find_models_dir()` 解析器，模型经 `electron-builder.yml` 的 `extraResources` 随包；`.kmod` 装的高精度模型落数据根 `models/`（`Paths.models`）。
- **离线铁律（FR-17）**：模型/二进制全部随包，运行期零下载；`offline_guard` 会拦非回环连接。下载模型只发生在**构建期/CI**，绝不进运行期代码路径。
- **降级透明**：新增能力一律沿用现有 `ParseEnv.degrade()` / `note_warning()` / `mark_level()` 出口，`degrade_policy=strict` 语义（宁可失败不要不完整）自动继承。

## 4. 分阶段计划

推荐串行主线 **P0 → P1 → P2 → P3 → P4 → P5**（按「缺失严重性」排序）；三大件 P1/P2/P3 **互相独立可并行**，Qwen tokenizer（P4）也独立、可提前插入。

### Phase 0 — 打地基（解锁后续所有阶段）

先把「能随包、能找到、能测」的管道铺好，否则三大件无处落脚。

- **模型目录解析器**：新增 `find_models_dir()`（env `DOCFACTORY_MODELS_DIR` → 内置 `resources/models` → 数据根 `models/`），仿 `find_soffice()`。
- **打包管道**：`electron-builder.yml` 的 `extraResources` 增加 `models` 与 `libreoffice`；`package` job 体积门禁增加「模型/soffice 存在性校验」（仿现有 `engine.exe` / `THIRD-PARTY-NOTICES` 校验）。
- **corpus 真实语料流程**：现在 21 份是程序化 fixtures（无损、覆盖率恒 1.0）。建立 `corpus/samples/` 真实语料 + `expected/*.expected.json` 标注的接入流程（双栏 PDF、跨页表、扫描件、旧格式）。
- **量化统计能力**：补 OCR P95 分位统计、TEDS 打分、阅读顺序正确率评分的骨架（现在 corpus 只有网格覆盖率）。
- **验收**：`find_models_dir` 单测；`resources/models` 缺失时能力优雅降级为「不可用」而非崩溃。

### Phase 1 — LibreOffice 随包（决策 D3，性价比最高）

`office_convert.py` 调用逻辑**已写完**，唯一缺口是随包 soffice。一次解锁两件事：旧格式 `.doc/.ppt` 转换 + **Office 页快照**（三栏对照的「原文」栏）。

- **构建脚本**：下载/裁剪 LibreOffice（剔除 GPL 组件：部分图标主题、PDF import 扩展），产物放 `resources/libreoffice/program/soffice.exe`——正是 `find_soffice._BUNDLED_RELATIVE` 已指向的路径。
- **Office 页快照**：`pdf_parser._render_preview` 已有 PDF 快照实现；docx/pptx/xlsx 三个 parser 现在一次没调快照。方案：解析 Office 前用 soffice 转一份 PDF 渲染 `preview/p{n}.png`，让三栏对照对 Office 用户成立（否则退化成两栏，「用户可亲自验证完整性」卖点对 Office 用户不成立）。
- **许可**：LibreOffice 版权声明 + 源码获取声明进 `THIRD-PARTY-NOTICES.txt`。
- **验收**：干净 Windows 机导入 `.doc/.ppt` 不再抛 E03；corpus 加旧格式 + 转换失真专项；Office 文档三栏对照有「原文」栏。
- **风险**：体积（裁剪版 ~300MB，占 2GB 预算大头）；soffice 卡死（已有 120s 超时 kill 重试兜底）。

### Phase 2 — OCR（决策 D2，丢内容最致命）

接入点 `pdf_parser._ocr_page()`；降级链、`env.ocr_pages`、`env.ocr_confidences`、E04 告警路径、`ocr_mode=="off"` 短路**都已就位**。

- **依赖**：RapidOCR（Apache-2.0）+ onnxruntime CPU EP（MIT），内置 PP-OCRv5 mobile 中英模型（~20MB 随包）。
- **实现 `_ocr_page`**：整页渲染位图 → RapidOCR 识别 → 映射成与 `_extract_page_items` 同构的条目 → 坐标回填 `prov.bbox` → 逐字符置信写 `env.ocr_confidences`（页均 < 0.6 记 E04，不判失败）。同时覆盖**文档内嵌图片 OCR**（figure 节点 `ocr_text`，docx/pptx/pdf 三处 `save_asset` 附近）。
- **AVX2 检测**：onnxruntime CPU EP 要求 AVX2（01 章 §2.4）——安装器/主进程/引擎三层补检测（属 M5，但被 OCR 触发，建议此处一并做）。
- **三档开关**：`on/off` 做实；`high`（server 模型 ~100-200MB）经 `.kmod`，依赖 M4 模组 loader 消费点（当前缺失），先标注依赖。
- **验收**：扫描件不再整篇 E05；corpus 加扫描件（含倾斜/低分辨率）+ 字符准确率标注；OCR P95 耗时进门禁。
- **风险**：CPU OCR 性能（按页多进程并行 `min(CPU-1,4)`、快速路径开关、mobile 模型控制）。

### Phase 3 — 版面分析 + 表格结构还原（决策 D1 / Docling）

接入点 `pdf_parser._try_docling()`。注释已明确「DoclingDocument → IR 单向映射写在这里，降级链/指标/取消都不用动」。

- **依赖**：IBM Docling（MIT），含 RT-DETR layout 模型（~100MB）+ TableFormer fast（146MB 随包；accurate 213MB 作可选 `.kmod`）。
- **版面分析**：RT-DETR 输出块类型（标题/正文/表格/图片/页眉/页脚/脚注/公式）与**阅读顺序**——解决双栏 PDF 现在逐行横读串栏（现按 top 单键排序）。
- **表格还原**：TableFormer 输出 cell 网格 + rowspan/colspan + 表头行标记，替换 pdfplumber 启发式（现 rowspan/colspan 恒 1、首行硬当表头）。
- **DoclingDocument → IR 映射**：核心工作量，覆盖 04 章全部 node type，写在 `_try_docling` 内，L1/L2 降级保持不变。
- **`_decide_status` 补回**：L0 落地后补回「全部页 L0」判定（现在锚在「降级/告警」上，TODO 已标）。
- **验收**：多栏阅读顺序 ≥90%；表格 TEDS 常规≥85%/复杂≥75%（实现 TEDS 打分）；`parse_level` 出现真正的 L0。
- **风险**：性能（RT-DETR ~3-5s/页，大幅改变基线）；内存（模型常驻 ~1.5GB，按页流式、禁止全文档位图驻留）。

### Phase 4 — 指标去假与配套（随模型接入落地）

前三阶段模型接入后，这些「空壳/假值/缺失」才有真数据来源：

- `table_confidence`：现恒 1.0 → TableFormer cell 置信均值（P3 后）。
- `ocr_confidence`：现恒 NULL → OCR 逐字符置信（P2 后）。
- `prov.bbox` / `charspan`：现无生产者 → 版面/OCR 落地后回填（连带解锁三栏对照的区域级高亮）。
- **跨页表合并**：`ir.py` 契约已预留，解析层未实现 → 相邻页表格 bbox 水平投影重叠 + 列数一致时合并（`long_table.pdf` 现解析成 4 张独立表）。
- **PDF 页眉/页脚/脚注识别、PDF 图片抽取落 assets、docx 脚注丢字**：TODO 均已列。
- **Qwen tokenizer**（**独立、可提前**）：现 `token_count` 是启发式估算（中文 1 字 = 1 token），与训练侧口径不一致。加依赖 + 打包 tokenizer.json + `configure_models_dir` 接上，对存量文档触发重切（越晚接重切成本越高）。

### Phase 5 — 冻结与门禁（M2 收口）

- **corpus 扩到 50+** 接入 CI；四项量化指标实现为可测量并设门禁。
- **重跑性能基线**并冻结（TODO 明确 M2 完成后必须重跑）。
- **IR v1.0 冻结**（04 章）+ 数据集 schema 冻结（05 章，属 M3 但契约相关）。
- **IR major 版本闸门 + `ir_outdated` 标记**（TODO 标 M2；现读到 `ir_version="2.0"` 会被当 1.0 静默解析）。

## 5. 顺序、并行与依赖

P0 打地基 ──┬─▶ P1 LibreOffice ─┐
            ├─▶ P2 OCR ─────────┼─▶ P4 指标去假与配套 ─▶ P5 冻结与门禁
            └─▶ P3 版面+表格 ───┘
                （P1/P2/P3 互相独立可并行；Qwen tokenizer 独立，可并入 P0/P1 时段）

- 两人分工建议：一人 P1（含打包/体积）、一人 P2→P3（模型接入主线）；Qwen tokenizer 谁先空出手谁做。
- P4 的各子项分别依赖 P2（ocr_confidence）/P3（table_confidence、bbox），跨页表合并依赖 P3 的 bbox。

## 6. 风险清单（TOP）

| 风险 | 触发阶段 | 缓解 |
|---|---|---|
| CPU 版面分析/OCR 性能不足 | P2 / P3 | mobile 级 ONNX、按页并行、快速路径开关、可取消；落地即实测，别等 P5 |
| 安装包体积逼近/超 2GB | P1 / P3 | LibreOffice 裁剪、accurate 模型与高精度 OCR 拆可选 `.kmod`；`package` job 体积门禁常态跑 |
| Docling → IR 映射覆盖不全 | P3 | corpus 真实语料驱动；L1/L2 降级永远兜底，映射失败不崩 |
| `high` OCR 依赖 M4 模组 loader（当前缺失） | P2 | 先做实 `on/off`，`high` 标注依赖 M4，不阻塞 P2 主线 |
| AGPL 依赖误入（如 PyMuPDF/MinerU/Ultralytics） | 全程 | 禁用清单 + CI `license_scan.py` 阻断；新依赖登记 03 章 §6 |
| 完整性指标口径歪 → 卖点指标长期误报 | P4 | 沿用 `visible_chars` 去空白口径；corpus 标注做回归锚点 |
